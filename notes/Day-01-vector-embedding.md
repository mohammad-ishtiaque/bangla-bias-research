## আজ যা শিখলাম

### ১. Vector
একগুচ্ছ সংখ্যা, পরপর সাজানো — `[0.2, −1.4, 0.9]`। একজন মানুষকে `[উচ্চতা, ওজন, বয়স]` দিয়ে বর্ণনা করার মতো। কম্পিউটার শব্দ বোঝে না, সংখ্যা বোঝে — তাই প্রতিটা শব্দকে vector-এ পরিণত করতে হয়।

### ২. Embedding
একটা শব্দ বা বাক্যের vector রূপ, যেটা model **training data থেকে শিখে নিয়েছে**।

মানসিক ছবি: একটা বিশাল মানচিত্র, প্রতিটা শব্দ একটা বিন্দু। "রাজা" আর "রানি" কাছাকাছি, "রাজা" আর "টেবিল" দূরে। প্রতিটা বিন্দুর coordinate = তার embedding।

> **এখানেই bias-এর জন্ম:** training data-তে "নার্স" যদি বেশিরভাগ সময় "মহিলা"-র পাশে আসে, মানচিত্রে ওরা কাছাকাছি বসে যাবে। Model ইচ্ছে করে পক্ষপাত করছে না — সে শুধু data-র প্যাটার্ন প্রতিফলিত করছে।

### ৩. ⭐ ৭৬৮ কোথা থেকে আসে — দুটো আলাদা প্রশ্ন

আজকের সবচেয়ে বড় সংশোধন। এই দুটো গুলিয়ে ফেলা যাবে না:

| প্রশ্ন | উত্তর | কখন |
|---|---|---|
| **কতগুলো** সংখ্যা? (= 768) | Researcher/architect ঠিক করেন — **hyperparameter** | Training-এর **আগে** |
| **কী কী** সংখ্যা? (মানগুলো) | Training process শেখে — **learned parameters** | Training-এর **সময়** |

**Analogy:** ফর্মে কতগুলো ঘর থাকবে → ডিজাইনার ঠিক করেন। ঘরে কী লেখা হবে → যে পূরণ করে তার ব্যাপার।

*(কেন ঠিক ৭৬৮? BERT-base-এ ১২টা attention head × ৬৪ মাত্রা = ৭৬৮। নিছক convention।)*

### ৪. ⭐ Static বনাম Contextual Embedding

| | Static | Contextual |
|---|---|---|
| **কী** | অভিধান খোঁজা — টেবিলে আগে থেকে লেখা | প্রতিবার নতুন করে হিসাব |
| **একটা শব্দের** | একটাই vector, চিরকাল | প্রতি বাক্যে আলাদা vector |
| **উদাহরণ model** | word2vec, GloVe, fastText | BERT, BanglaBERT, GPT |

**Bangla উদাহরণ — "কল":**
- "পানির **কল** বন্ধ করো" · "তোমার **কল** ধরিনি"
- Static → দুটোই **একই** vector (ভুল)
- Contextual → **আলাদা** vector (ঠিক)

**সূক্ষ্ম কিন্তু জরুরি:** contextual embedding "বাক্যের অর্থ" নয় — এটা **ওই শব্দটার অর্থ, বাক্য দ্বারা প্রভাবিত হয়ে**।

### ৫. ⭐ কেন এটা পুরো field-এর ভিত্তি

```
Static embedding  → একটা শব্দের একটা vector → cosine দিয়ে সহজে bias মাপা যায় → WEAT
Contextual        → একটা শব্দের অসংখ্য vector → WEAT ভেঙে পড়ে → SEAT → CEAT → LPBS
```

Day 16–29-এর পুরো paper-লাইনটা আসলে **এই একটা সমস্যার সমাধানের ইতিহাস**। আজ যেটা শিখলাম, ওখানে গিয়ে কাজে লাগবে।

## কোড থেকে যা শিখলাম

```python
tok = AutoTokenizer.from_pretrained("csebuetnlp/banglabert")
model = AutoModel.from_pretrained("csebuetnlp/banglabert")

s = "আমি ভাত খাই।"
inputs = tok(s, return_tensors="pt")
with torch.no_grad():
    out = model(**inputs)

print(tok.tokenize(s))              # ['আমি', 'ভাত', 'খাই', '।']
print(out.last_hidden_state.shape)  # torch.Size([1, 6, 768])
```

### ⭐ ৪ বনাম ৬-এর রহস্য

`tokenize()` ৪টা token দেখালো, shape বললো ৬। **কারণ model input-এ দুটো বিশেষ token যোগ হয়:**

```
[CLS]  আমি  ভাত  খাই  ।  [SEP]
  ↑                        ↑
শুরুর চিহ্ন            শেষের চিহ্ন
```

- **`[CLS]`** = classification token, বাক্যের শুরুতে। এর embedding-কে প্রায়ই পুরো বাক্যের প্রতিনিধি ধরা হয়
- **`[SEP]`** = separator, বাক্যের শেষে

`tokenize()` এগুলো দেখায় না, কিন্তু model এগুলো নিয়েই কাজ করে। **কালকের sentence vector-এর প্রশ্নের উত্তর এখানেই লুকিয়ে।**

### Shape পড়ার নিয়ম
```
torch.Size([1, 6, 768])
             │  │   └── প্রতি token-এ ৭৬৮টা সংখ্যা (embedding মাত্রা)
             │  └────── ৬টা token ([CLS] ও [SEP] সহ)
             └───────── ১টা বাক্য (batch size)
```

### `torch.no_grad()` কেন?
আমরা শুধু ভবিষ্যদ্বাণী নিচ্ছি, model শেখাচ্ছি না। Gradient হিসাব বন্ধ রাখলে memory বাঁচে ও দ্রুত চলে। **প্রতিটা inference-এ এটা ব্যবহার করবে।**

## আজকের এক-বাক্যে সারাংশ

> Embedding হলো শব্দের সংখ্যা-রূপ যা model **data থেকে শেখে** — আর data-তে যা প্যাটার্ন আছে, সেটাই vector-এর geometry-তে বসে যায়; **এই geometry-ই bias**, এবং static থেকে contextual-এ যাওয়ার কারণেই bias মাপার পদ্ধতি বারবার বদলাতে হয়েছে।

## কাল (Day 2) কী আসছে
**Cosine similarity** — দুইটা vector কতটা একই দিকে মুখ করে আছে। NumPy-তে নিজে লিখব, তারপর `cos("নার্স","মহিলা")` বনাম `cos("নার্স","পুরুষ")` — **জীবনের প্রথম bias measurement**।
